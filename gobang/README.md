# 优雅五子棋（Gomoku）

15×15 棋盘的五子棋，支持双人对战与人机对战，单文件约 1500 行。

![对局截图](screenshot.png)

## 运行

```bash
python -m pip install pygame
python gobang.py
```

## 玩法

| 操作 | 说明 |
| --- | --- |
| 鼠标左键点棋盘 | 落子；悬停时会显示半透明预览棋子 |
| `Ctrl+Z` | 悔棋 |
| `R` | 重新开始 |
| `ESC` | 退出 |

右侧面板还有四个按钮：切换模式（双人 / 人机）、再来一局、悔棋、退出游戏。
程序只响应左键点击（`event.button == 1`），右键没有绑定功能。

## 代码结构

单文件里分成三层，互相不耦合：

| 类 | 职责 |
| --- | --- |
| `GomokuBoard` | 棋盘状态（`grid[row][col]`，0 空 / 1 黑 / 2 白）、落子、胜负判定、悔棋 |
| `GomokuAI` | 选点。全部是 `@classmethod`，不持有状态，纯函数式计算 |
| `GomokuRenderer` | 绘制：木纹棋盘、棋子阴影、悬停预览、获胜连线高亮、右侧面板 |

## AI 是怎么选点的

**没有用博弈树搜索（minimax），而是走评分制**——遍历所有空位，给每个候选点算一个「攻防综合分」，取最高分。

### 1. 棋型评分表

对每个候选位，沿四个方向统计连续同色棋子数与开口数，查表得分：

| 棋型 | 分值 | 棋型 | 分值 |
| --- | --- | --- | --- |
| 活五（连五） | 100000 | 活三 | 8000 |
| 活四 | 50000 | 眠三 | 800 |
| 眠四 | 8000 | 活二 | 800 |
| 眠二 | 80 | 活一 | 80 |
| 眠一 | 10 | | |

分值级差约 10 倍，这样「一个活四」的权重一定高于「若干活二之和」，高阶棋型不会被低阶棋型的数量淹没。
「活」指两端都空（更难防守），「眠」指只有一端空。

### 2. 攻防综合分

```python
offense = _evaluate(grid, r, c, WHITE)   # 我在这里落子能得到多少
defense = _evaluate(grid, r, c, BLACK)   # 对手在这里落子能得到多少
score   = offense + defense * 1.1        # 防守权重略高于进攻
```

`DEFENSE_WEIGHT = 1.1` 让 AI 优先封堵对手的威胁，而不是一味进攻。这个 1.1 是个经验值：
再高会过于保守（只顾堵、不发展自己的棋），再低则挡不住对手的活三。

### 3. 其它细节

- 首手固定落在天元 (7, 7)。
- 多个候选点同分时，优先选离天元更近的位置——保持联络，避免孤子。
- 复杂度 `O(N × D)`，N 是空位数（最多 225），D 是方向数（4），实际是毫秒级。

### 为什么不用 minimax

五子棋的分支因子约 200，做三层搜索就要评估上百万个局面，纯 Python 会卡顿。
而这个评分表在「一眼看出活四该堵」这类常见局面上表现已经够用，代码也短得多。

## 已知不足

- **没有前瞻**：只看单步得分，遇到「双活三」「四三杀」这类复合威胁会顾此失彼，
  因为堵住一边之后另一边的分还不够高。想提升可以在这张评分表之上加一层 2～3 层的浅层搜索。
- **评分表是拍脑袋定的**：10 倍级差和 `DEFENSE_WEIGHT` 都是手工调的，没有做过对局胜率的批量验证。
  更严谨的做法是让两个不同参数的 AI 互相对打若干局，用胜率来调参。
