# 文献解读助手

一个上线在扣子（Coze）商店的论文解读智能体，用来把一篇论文快速读成能用的东西。

**在线体验：<https://www.coze.cn/s/y4QOPYiCD-4/>**

> **投递前请核对这一份 README。** 下面的「设计思路」「检查清单」「迭代记录」是按常见做法写的框架，
> 需要你对照自己实际做的版本改一遍：面试官很可能顺着这里往下问，写得不符反而扣分。
> 凡是自己记不清的，宁可整段删掉，也不要留。

## 解决什么问题

读一篇不熟悉的论文时，最花时间的不是读，而是搞清楚「它到底解决了什么、凭什么说自己有效、跟我有什么关系」。
这个智能体把这三件事固化成一个流程：

1. **这篇论文想解决什么问题**（问题、动机、已有方法的不足）
2. **它是怎么做的**（方法主干、关键设计、必要的公式解释）
3. **结论站不站得住**（数据集、指标、对比基线、有没有夸大）
4. **跟我有什么关系**（能用在什么场景、有哪些前提条件、局限在哪）

## 设计思路（待你核对）

### 输出结构化，而不是让模型自由发挥

直接问「帮我总结这篇论文」，模型很容易写成一段面面俱到的流水账，读完仍然不知道重点是啥。
所以提示词里把输出拆成固定的小节，每节还规定了「如果原文没有提到，就写『原文未说明』」——
不允许它用听起来合理的话把空缺填上。

### 显式约束「不要编」

大模型解读文献最典型的问题就是**凭空补充**：把常识当成论文结论、把别人的工作算到这篇头上、
把「在某个数据集上有效」说成「普遍有效」。因此提示词里明确要求：

- 数字（数据集规模、指标数值）必须来自原文，不能由常识推断；
- 区分「论文声称」和「客观事实」；
- 原文没写的地方直接说没写。

## 输出质量检查清单（待你核对）

模型顺着写容易跑偏，所以我用一个固定的清单人工抽查它的输出，每次迭代完就过一遍：

| 检查项 | 怎么判断 |
| --- | --- |
| 结构完整 | 四个小节是否都写到了，有没有整节漏掉 |
| 术语准确 | 关键术语有没有翻错或自造（比如把 attention 解释成「注意力机制」之外的奇怪说法） |
| 是否凭空编造 | 随便挑 2～3 个具体数字，回到原文核对 |
| 有没有回答「跟我有什么关系」 | 最后一节是否具体，还是一句正确的废话 |

哪一项反复出问题，就回去改那一小节的提示词或补一条例子，而不是整段重写。

## 迭代记录

> 这一节留给你补充真实记录。写简历和面试时，这里是最有说服力的部分——比如：
>
> - v1：直接让模型总结，四个小节经常漏掉「局限性」；
> - v2：把局限性改成必填项，并给了两个例子，漏项问题消失；
> - v3：发现它会把综述里的引用工作当成论文自己的贡献，于是在提示词里区分「本文提出」与「引用他人工作」；
> - 仍未解决：中文论文里出现英文缩写时，解释往往不到位。

## 已知不足

- **长文献会被截断**：超出上下文窗口的部分直接丢掉了，模型不会主动提示「我没读到后面」，
  这是目前最需要修的问题。
- **没办法核对原文**：现在完全靠模型自己说，没有做「引用定位」——
  理想情况是每条结论后面能标出论文里的哪一页哪一段。
- **只做了人工抽查**：没有构建固定的测试集，所以迭代时无法量化「这一版比上一版好多少」，
  只能凭感觉。这是下一步最想补的。
